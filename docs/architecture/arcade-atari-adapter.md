# Atari ST disk-set adapter

Introduced 2026-09-07 by Arcade 0.2.29, Host 0.2.16, Relay 1.1.10 and Portal 0.12.18.

Arcade owns `atari-st-disks-v1`, a read-only collection of already sorted disk images. `Arcade/tools/configure_atari.py` previews discovery; `--apply` adds the collection and fixed STEem emulator with a configuration backup. Images and emulator preferences remain intact. Existing differing metadata requires review. Configuration and generated `collection-metadata.json` stay outside the checkout.

One metadata record describes one complete edition with ordered relative disk paths. ST/STX/MSA/DIM/STT images are supported. Discovery retains language, hardware, revision and release distinctions and rejects bad or incomplete sets; setup refuses unresolved images. It does not deduplicate an unsorted collection. Title grouping and shared defaults use the existing version model; disks are not separate versions. Paths are confined after real-path resolution. Unspecified language stays unspecified.

Atari is a separate Arcade platform, with ST/STe/TT/Falcon hardware badges and the Atari favicon. TT/Falcon editions remain browseable but cannot launch in STEem. TheGamesDB uses Atari ST instead of Spectrum. Arcade 0.2.33 supports presentation-only scrape overrides as described below.

The optional `arcade-atari-st: 1` capability is advertised by Arcade, Host, Relay and Portal. Relay enables it for an authenticated catalogue session through the fixed native `ARCADE_CATALOGUE_ENABLE_ATARI` operation when the registered page also advertises it. This is independent of ScummVM support. Older clients retain their existing entries; ScummVM ports with platform `atari-st` do not authorize native `disk-set` targets.

Arcade resolves the exact source-scoped edition without changing the active collection. Native plan schema 3 contains every ordered disk, signature and SHA-256, executable signature, hardware and fixed arguments. Host independently checks all members, including disks beyond drive B. The approval fingerprint covers ordered relative paths, disk contents and hardware. Portable Portal records contain presentation and an opaque gameKey, never native paths or arguments.

STEem arguments are `OPENNEW`, `INI=<executable-directory>/steem.ini`, the first disk for drive A, and optionally the second for drive B, following STEem SSE's bundled `doc/readme.txt` command-line documentation. Additional disks remain in the game folder for manual swapping. The adapter retains existing TOS and machine preferences; it does not change hardware configuration automatically. The STEem build must match the installed Pasti DLL architecture for STX images.

The first approved Atari binding atomically upgrades the native catalogue binding store from schema 1 or 2 to schema 3. Existing Spectrum/ScummVM approvals, opaque keys, receipts and revisions are preserved. Schema 3 adds steem exact-entry policies whose mediaSha256 covers the complete ordered set and hardware. New Hosts read all three schemas; writes never downgrade schema 3. Older Hosts reject schema 3 safely. Restoring a pre-upgrade backup requires an explicit rollback and must not silently overwrite newer approvals.

Validation uses synthetic disk sets, mocked processes, independent hostile-plan and capability tests, and isolated Firefox acceptance (`tools/validate_game_picker_firefox.py --atari`). Live game boot and disk swapping require a separately authorized emulator session.

## Edition Properties — Arcade 0.2.31 / Host 0.2.17

The authenticated Arcade-only native API exposes GET/POST `/api/game-properties`, POST `/api/game-properties/pick-save` and POST `/api/game-properties/recover`. Requests identify a configured collection and stable edition; they accept no native path or arbitrary command. The native picker returns a short-lived opaque import token bound to that edition and source hash. The existing Arcade role boundary denies these operations to Portal.

Settings live in the Arcade runtime under `game-properties/<collection-root-identity>.json`, schema 1, keyed by edition ID. Each record contains emulator ID, opaque named profile ID, drive B choice (`empty`, `game:N`, `save`) and a confined save-image basename. Compare-and-save revisions and a native writer lock reject stale changes. A pending journal precedes image/settings changes; explicit recovery completes approval of committed settings or retains an orphan image without deleting user data. Cancel never invokes the mutation API.

Images live under `<game folder>/Safe Disks`, never portable catalogue data. New disks contain a non-bootable 720 KiB FAT12 filesystem, 80 tracks, two sides and nine sectors per track. Import supports bounded raw `.st` images only and copies on Save without overwriting. Restore checks the backup content hash and backs up current data before atomic replacement. `.backups/<filename hash>` retains ten distinct recent versions. Discovery excludes Safe Disks and hidden directories. Atari catalogue watches collection identity, metadata and properties, not the directory modification time or mutable save contents.

An edition with saved Properties uses native plan schema 4. This extends schema 3 with an exact profile path/signature/hash, confined private session directory, selected drive B target and optional save target. Host independently reconstructs every expected argument and validates original disks, executable, profile identity and confinement. Save contents are deliberately excluded from the approval fingerprint, while their target is included. An explicit Properties save refreshes matching native policies without changing opaque Portal keys; arbitrary external profile/media changes still require review. Default selection uses the existing shared version mechanism. Editions without saved Properties keep their schema-3 launch path; older Hosts fail closed for schema 4 and cannot service Properties without the required native callbacks.

STEem SSE's bundled `doc/readme.txt` documents `INI=<filename>` and ordered A/B disk arguments. Named configurations are read from `<emulator>/config/*.ini` and identified by a hash of the filename. Host writes `<game>/Safe Disks/.sessions/<edition>/launch.ini`, preserving source encoding and preferences, but clearing remembered disks, disabling automatic second-disk insertion and automatic snapshot loading/saving. `OPENNEW`, the private INI, game disk 1 and optional chosen drive B are fixed argument-array entries. Original profiles are never passed to STEem after Properties are configured.

Before launch, Host locks both the edition session and mounted save image, backs up the latter, and records the child's PID plus process creation identity in native runtime `save-sessions` records. These leases survive Host reloads and reject concurrent use, including across editions. Exited or reused PIDs release a lease on the next access. An interrupted launch before its child identity is recorded remains blocked for native review; never unlock that ambiguous state automatically. These controls cover Cyrune launches and do not police manually started external emulators. Original game disks are not made write-protected by this feature.

## Immediate save-disk actions — Arcade 0.2.32

The Arcade-only POST `/api/game-properties/save-disk` accepts exactly collection ID, edition ID and `action`: `create`, `import` (plus an opaque native-picker token) or `restore` (plus confined basename and validated backup ID). It performs that explicit disk action immediately and returns refreshed choices with `selectedDisk`; it accepts no launch settings, profile, default change or browser-native path. Existing staged `diskAction` requests on the Properties save route remain compatible with older open pages. The new UI uses that route only with `kind: none` to commit launch settings.

The selector lists valid compatible images, a divider and direct create/import options. Creation and import use edition-aware automatic names and numbered collision suffixes. The dialog stays open, selects the new disk for drive B and preserves the emulator/profile/default draft and its original comparison revision. Cancelling a picker restores the selection; cancelling Properties discards only the launch-settings draft. Explicit disk operations survive Cancel. Backup restore is a separate direct button in an expandable section.

`Safe Disks/.editions.json` is a bounded native schema-1 map of case-folded basenames to stable edition IDs. A per-folder writer lock serializes name allocation. Ownership is atomically reserved before publishing a completely written image with exclusive rename on Windows (exclusive link on Unix), so an interrupted create can leave only an unused name reservation or a correctly owned disk. Failed publication rolls the reservation back. No existing image is overwritten; import reads the source again and checks its picker-time digest. Restore validates the backup digest, preserves current data and atomically replaces the image. Existing Host session leases guard disk actions against an active Cyrune emulator session.

Choices exclude images explicitly owned by other editions, older files assigned to another edition or named for its automatic default, malformed images and confined-path failures. An edition's existing explicit selection preserves legacy sharing. Unassigned raw `.st` files in the same game folder remain selectable; their save-game contents cannot establish semantic compatibility automatically. Ownership and disk operations do not alter Portal bindings or launch-settings revisions.

## Scraped metadata — Arcade 0.2.33

The existing Arcade-only `/api/apply-scrape` route now supports Atari ST even though the source collection is read-only. Generic metadata/file mutations remain blocked. Validated presentation fields and approved HTTPS artwork references are atomically stored in `atari-overrides/<collection-root-scope>.json` under the native Arcade runtime, using the existing bounded schema-1 presentation override shape. No source disk, metadata file, save disk or launch property is rewritten. Artwork uses the existing optional-network display policy; saving a reference does not download offline artwork.

Overrides bind a stable game ID to the ordered relative disk set, hardware, languages and countries. Another source or a retargeted edition does not inherit them. The library and catalogue refresh from the same override store; catalogue revisions change for new presentation while the original title supplies the family identity. Exact catalogue IDs, shared defaults and approved native launch policies remain intact. Existing ScummVM storage paths, schema and scope identities are preserved by the shared presentation validation/persistence implementation.

## Hatari — Arcade 0.2.34 / Host 0.2.19

The fixed `hatari` emulator adapter supports ST/STe/TT/Falcon disk sets in ST/STX/MSA/DIM formats; STT remains STEem-only. Machine, TOS and peripheral preferences come from the selected emulator configuration; Arcade does not guess a matching ROM or rewrite machine settings. A compatible machine profile is still necessary for the selected hardware.

`Arcade/tools/configure_hatari.py` previews or registers an installed executable with an atomic configuration backup. It preserves collections and their STEem defaults. Properties selects Hatari and an optional named profile per edition. Arcade's emulator menu can also request one launch in an alternative configured Atari emulator; that override uses its own default profile, retaining the edition's drive B choice, and does not change persisted Properties or Portal approvals. The override is confined to the private native execution path; catalogue binding resolution continues to use saved defaults.

Hatari's [manual](https://hatari.tuxfamily.org/doc/manual.html) and bundled documentation specify `--configfile <filename>`, `--disk-a <file>` and `--disk-b <file>`. Profiles are bounded files immediately within `<executable-directory>/configs`, including extensionless filenames such as names ending in a TOS version number. IDs hash the complete case-folded filename; presentation never exposes the path. The default is a confined `hatari.cfg` beside the executable when present, otherwise `%LOCALAPPDATA%/Hatari/hatari.cfg`. All files must resolve within their declared directory; missing profiles fail without substitution.

Hatari always uses native plan schema 5, with the same exact field shape as schema 4 and `adapterId: hatari`. Host independently validates supported disks, hashes, profile identity and confinement, then reconstructs the exact arguments: `--configfile <session>/launch.cfg --disk-a <first-game-disk>` plus optional `--disk-b <chosen-image>`. It writes a private CFG copy, clears remembered A/B and archive paths, disables automatic B insertion and automatic memory snapshots, enables both drives, and selects floppy boot. Source profile encoding and remaining preferences are retained. The existing edition/save-image leases and backups apply to both emulators. The original named/default configuration is never passed to Hatari for a Cyrune launch.

The first Hatari approval, including an explicit Properties change to a previously approved STEem entry, upgrades the native catalogue binding store to schema 4 atomically. It adds Hatari exact-entry policies while retaining prior schemas 1–3, keys, receipts and revisions. Switching back to STEem does not downgrade the store. Older Hosts reject schema 4 safely. The existing optional `arcade-atari-st: 1` transport and portable opaque-key format are unchanged; no profile paths or launch arguments enter Portal data.

## Added images and disk presentation — Arcade 0.2.35

The explicit Arcade Rebuild operation now scans the active Atari source for media absent from its native `collection-metadata.json`. It discovers complete TOSEC sets, retains alternate-dump distinctions, and appends only new records. Existing records and IDs are not regenerated, retargeted or deleted, including records whose media is missing. Thus favourites, metadata overrides, version defaults, Properties and native binding identities remain valid. Newly incomplete sets are omitted until all members are present; existing indexed disks are not borrowed to fill a new set. Safe Disks and maintenance directories remain excluded.

The index write is bounded and validated under the native metadata writer lock, with a content-keyed backup, a comparison check and atomic replacement. Repeated scans with no additions do not rewrite the index. This explicit metadata-maintenance exception does not make source game images writable or enable generic collection edits. Catalogue watches detect the index replacement, including while another collection is active.

Arcade-only `/api/game-versions` adds `imageFiles` basenames for disk sets and Spectrum media. Properties adds the basename to each `gameDisks` entry. These fields do not enter portable catalogue versions or Portal records. Dialogs render names as text, wrap long names, show every image in a set and retain the extension. Properties separates shared game disk choices from the default emulator/profile controls. The existing settings schema and per-edition ownership are unchanged: changing emulator never changes or copies its save image or Drive B selection; named emulator profiles remain adapter-specific.

Arcade 0.2.36 adds `gameId` and `collectionId` to the same Arcade-only version response. Properties obtains its selector from a fresh response, independently of cached or filtered page groups. Launch Version uses image filenames as primary labels and refreshes page summaries before resolving a launch. These private fields do not change portable catalogue versions, native approvals or persisted identifiers. Versioned app/CSS asset URLs match the Arcade component release so normal page reloads obtain the current dialog code.
