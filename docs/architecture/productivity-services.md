# Browser productivity services

Relay 1.4.0 is the authority for one Focus timer and optional browser activity in a Firefox profile. Portal 0.13.0 transports fixed authenticated requests; Widgets 0.5.0 provides controls and reports. Host and Nexus have no productivity-data operations. Firefox must remain running; this is browser activity, not whole-computer time tracking. Different profiles have independent records.

## Storage and recovery

Relay's `cyruneProductivityV1` IndexedDB database version 1 with current state schema 4 contains `state`, detailed `segments` and daily `days` stores. State, activity checkpoints, aggregates and deletion commit in one read/write transaction. Failed commits retain prior records and do not replace live authoritative state. Unsupported/corrupt state fails closed with recovery guidance. Back up the Firefox profile to preserve these records; clearing extension data or uninstalling Relay can remove them. Portal exports contain presets and view configuration, never browsing records.

One Focus clock uses an absolute deadline and a Firefox alarm. Unexpired deadlines survive restart. An expired deadline at startup, or one observed over a minute late, records one interrupted phase and pauses the next phase; no chain of completed work is inferred from downtime. Auto-start applies only to an observed normal completion. Background sampling uses a monotonic elapsed clock, drops gaps over 45 seconds and never backfills activity while Firefox is closed. Intervals split at local midnight and focus phase boundaries.

Focus history retains at most 2,000 phases. Active legacy widget-local timers are no longer executed. Each widget explicitly offers history import or adoption as a paused timer. The supported baseline is the previous Focus SDK `runtime` cache with at most 120 phases. Relay validates and commits a copy of that snapshot, imported history and migration receipt before cancelling its old notification. The original widget cache remains a recovery source. At most 32 different widget snapshots can be adopted; repeats do not duplicate history. Adoption cannot replace an active shared timer. No shared Portal schema migration or live native-data migration occurs.

## Activity consent and privacy

Tracking defaults off. Enabling it in Browser Activity is explicit profile-local consent; the toolbar can pause/resume already enabled tracking. Only the active, non-discarded, non-private HTTP(S) tab in the focused normal Firefox window is eligible. Locked/idle users, unfocused windows, credentials in URLs, localhost/127.0.0.1 and excluded hostnames contribute no new intervals. The idle cutoff is configurable from 60 to 1,800 seconds. This cutoff deliberately permits short reading pauses and is not an attention measurement.

Records contain hostname, local date, elapsed milliseconds, interval timestamp, opaque phase/session ID and work/break/outside classification. Paths, queries, fragments, page titles, text, keystrokes and screenshots are never persisted. Exclusions and category assignments use registrable domains, including subdomains, resolved through the bundled ICANN and PRIVATE Public Suffix List. Shared hosting sites remain separate. See [PSL provenance](public-suffix-source.md). Excluding a site stops future collection; use Delete to erase its existing records. Private-tab URLs are rejected before parsing or persistence.

Detail retention is 7, 30 or 90 days (default 30), capped at 20,000 intervals. Daily aggregates retain up to 365 days / 50,000 rows, including per-phase attribution. Oldest records are evicted at the next write. Reports label these limits. Deletion atomically removes both detail and aggregates for the selected date range and optional hostname; empty scope deletes all. The widget keeps only view choices on disk and may show an in-memory, timestamped offline report with mutation controls disabled. Reloading an unavailable widget does not resurrect deleted records from a widget report cache.

Reports aggregate daily totals independently of detail retention. Export returns the same totals plus the most recent 1,000 retained intervals for that filter, explicitly marked when truncated. Choose a smaller range or hostname to narrow an export. No automatic upload or sync exists. The optional daily budget sends one reminder when time on sites flagged Distracting reaches its threshold; it does not block sites.

## Authenticated interface

`MW_PRODUCTIVITY` is available only to the exact authenticated Portal tab, URL, role and session. Ordinary web pages and Arcade/Nexus roles cannot call it. The main extension popup may use `CYRUNE_PRODUCTIVITY`; the refresh-only popup cannot. Registration is checked before queued work, immediately before a mutation commits, and before replying. Revision pushes contain a numeric revision only.

The schema-1 envelope has `schemaVersion`, `service`, `action`, `args`, optional `expectedRevision`, and a bounded `requestId`. Requests are capped at 128 KiB. Allowed focus actions are state/start/pause/resume/skip/stop/adopt; activity actions are state/report/settings/site/delete/export. Unknown fields/actions fail. Focus mutations compare the timer's own revision, independent of sampling checkpoints. A 64-entry receipt journal makes command retries idempotent and rejects a reused request ID with different content. Settings are fixed typed fields, with up to 256 excluded domains and 256 domain/category assignments (category labels at most 60 characters).

Reports accept local date range, exact hostname, opaque session ID and detail flag, with bounded site/session lists (200 each). Activity is attributed to the observed phase ID and phase type, so elapsed Focus time remains distinct from measured active browsing. Phase start/completion notifications use Relay's existing browser notification history/click routing and a durable pending event. Opening/removing a widget never starts, launches bookmarks for, or stops the shared timer. Optional bookmark/Set launch helpers execute only following an explicit successful Start in a widget.

## Validation

`Relay/tests/test_productivity.cjs` exercises clocks, restart, interrupted recovery, idempotency, stale/revoked commands, failed writes, explicit adoption, opt-in, privacy, filtering, phase attribution and deletion. Widget/SDK tests cover descriptors, authority and persisted view boundaries. `tools/validate_productivity_firefox.py` uses disposable Firefox and native-data roots to exercise real widgets, shared controls, Portal-closed alarms/notifications and hostname-only collection/deletion. The coordinated validator covers integration, packaging and lint.


## Domain controls and site blocking (Relay 1.3.0)

The address-bar clock opens Timer & Activity Tracker with separate reload, unload, activity and blocking cards. Reload timer saves one enabled flag and interval per whole domain; each eligible tab retains its own alarm and edited-form/loading/discarded/private safeguards. Activity has a current-domain category dropdown (agreed defaults plus retained custom values) and exclusion checkbox. Site blocking has independent daily-schedule and running-work-phase options. Either active rule blocks access. Times are local HH:MM, start inclusive/end exclusive; overnight ranges are supported, equal endpoints rejected. Breaks, paused timers and stopped focus allow access. Exclusion from tracking does not disable blocking.

`cyruneRefreshDomainsV2` schema 2 migrates supported `cyruneRefreshPagesV1` schema 1 records at load. The original key is retained intact as a recovery source. Identical page choices collapse into one domain record; conflicting intervals or enabled flags retain the first URL-sorted interval but pause the domain timer. The new record includes bounded conflict metadata. Future writes use only schema 2. Switching off retains an interval; Forget removes it. Migration and saves write one complete browser-storage record before replacing in-memory state. Unsupported or malformed records are retained and refused.

Productivity state schema 1 migrates atomically to state schema 2 in its existing IndexedDB database. `domainMigration` retains the old activity settings as a recoverable backup. Category keys and exclusions normalize to registrable domains; an explicit apex assignment wins over subdomain assignments, otherwise the first hostname in sorted order wins. Existing custom labels survive. Historical intervals stay hostname-only; report categories resolve through the domain map. Supported current callers use `activity/site` for bounded single-domain updates, avoiding replacement of unrelated site choices.

`cyruneDomainRulesV1` stores up to 256 domain rules, each with boolean schedule/focus flags and validated from/until times. Invalid times, unknown fields, stale popup tabs/domains and failed storage writes cannot replace confirmed rules. The `CYRUNE_SITE_CONTROLS` route accepts only Relay's exact address-bar popup document. `CYRUNE_BLOCK_STATUS` accepts only the extension's blocked-page mode and returns that domain's sanitized reason; it exposes no settings, paths or original URL. Blocked pages reuse the existing packaged popup HTML/CSS/JS and retain the eight-file XPI allowlist. The public page has no privileged control handlers. The normal popup's privileged routes retain exact document checks.

Firefox webRequest/webRequestBlocking intercepts top-level HTTP(S) requests and redirects matching navigation to the extension's empty blocked-page mode before the destination loads. The page shows a large centered rule explanation and domain; no original path/query is stored or forwarded. Blocking also covers already-open matching tabs on rule activation, focus start, alarm boundaries, startup and a 15-second reconciliation tick. Private navigation is blocked where Firefox grants Relay private-window access, without collecting private activity. Browser-protected pages remain outside HTTP(S) blocking. Ending a restriction never automatically reloads the original page: reopening remains explicit. The clock remains available on Relay's blocked page to edit that domain's rules.

Idle cutoff, detailed-interval retention and the Distracting budget live in Browser Activity's settings modal as a transient service-backed draft. Opening, editing or cancelling does not mutate Relay. Done sends only changed global fields through the SDK and waits for persistence; failure leaves the dialog open. Values stay out of widget.config/data. The report widget offers a dropdown of recorded sites for export/deletion filtering and no manual category/domain entry.


## Compact automatic edits and independent distraction flags (Relay 1.4.0)

The address-bar cards contain labels and controls without routine explanatory footers or confirmation buttons. Checkboxes and dropdowns save immediately. Numeric/time inputs save valid edits after 250 ms and flush on change/blur. Incomplete HH:MM, equal enabled schedule endpoints, or invalid intervals do not replace saved rules; concise inline errors are shown only when needed. Controls remain editable while requests persist. Each valid snapshot is dispatched to Relay immediately, where existing serialized queues commit in order; an older error response cannot replace newer feedback. No frontend save queue is lost when a popup closes. Disabling the timer retains the interval, so its former Forget action is no longer exposed in the UI.

The category list is alphabetical, including retained custom categories, with Uncategorized last. Default categories are E-commerce and online retail; Marketplaces and auctions; Communication and messaging; Social networks and online communities; News and journalism; Entertainment and streaming; Gaming; Education and e-learning; Reference and knowledge; Search and discovery; Business and professional services; Finance and payments; Health and wellness; Travel and transportation; Food and dining; Government and public services; Technology and software; Real estate and housing; Nonprofit, charity, and advocacy; and Personal, portfolio, and creator websites. Distracting is an independent checkbox in the activity card and is excluded from category choices. Category reports use the same ordering. A site can be Social and Distracting simultaneously.

Productivity state schemas 1/2 migrate at load through schema 3. Schema-1 domain normalization first retains its existing recovery backup. Schema 2 then copies activity preferences to `distractionMigration.backup`, converts legacy Distracting category assignments (case-insensitive) into bounded `activity.distractingDomains` flags, and changes that category to Uncategorized. Existing non-Distracting categories are unchanged; both previous uncategorized spellings normalize to Uncategorized. This conversion commits atomically before replacing live state. At most 256 domains may be flagged. Activity/site mutations carry a required boolean distracting field independently from category/excluded. New category writes cannot reintroduce Distracting as a category.

Reports expose distractingMs separately from category totals, and the daily budget counts all flagged sites across categories. As with category mappings, current flag assignments apply to retained history without rewriting original intervals. Report widgets display a compact distracting total when nonzero. Flags remain browser-local and absent from portable widget configuration.

## Inactive tab unloading (Relay 1.5.0)

Relay alone owns unloading through Firefox tabs.discard. The exact clock popup may use CYRUNE_TAB_UNLOAD; pages, widgets and other popup modes cannot. Browser-local cyruneUnloadDomainsV1 schema 1 retains up to 256 domain/enabled/seconds rules, with integer intervals from 60 to 86400 seconds. No browsing history, original URL, form values or tab IDs enter this record. Unsupported records are retained and refused; failed saves leave confirmed choices intact.

Each background tab has its own transient inactivity baseline. Selection resets it; background navigation/reloads do not postpone it. Restarts clear stale alarms and grant a full interval to open tabs. Active, pinned, private, loading, discarded, audible, muted and edited-form tabs cannot unload. Muted tabs are conservatively protected because Firefox can report their audio as inaudible. A final content-script probe must explicitly report a clean form, followed by a fresh tab and generation check. Trusted frame input/change notifications protect the whole tab; late-injection scans conservatively protect existing standard text/file drafts and report only a boolean. Missing handlers fail closed and retry after a minute. Edited-form protection clears on navigation/reload. These protections have no configurable exceptions yet.

Firefox retains the discarded tab and restores it when selected. The reload service clears alarms on discard and resumes on restored-page completion. Background reloads cannot keep an inactive page alive indefinitely. Unloading settings work with Portal and Host closed and do not alter their contracts or the eight-file extension allowlist. Relay service tests use injected clocks; tools/validate_productivity_firefox.py --unload exercises a real one-minute alarm, audio/forms, reload suspension and Firefox restore in disposable data.

### Timer reliability and visible state (Relay 1.5.1)

The shared dirty flag now follows trusted user input/change events. Synthetic site events and populated contenteditable markup, selects, checkboxes and sliders cannot establish an edit merely by existing. Initial document-start injection observes subsequent real edits in every injected frame. Late injection conservatively protects pre-existing standard text/file drafts; prior rich-editor edits cannot be inferred reliably from markup alone. Reload existing pages after upgrading so their previous handlers and sticky false-edit flags are replaced.

Clock-only state replies include transient per-tab reason, next deadline, last completed action and last skip. No URL or form content enters these records; close/restart clears them. Popup polling displays runtime feedback without replacing settings drafts or changing alarm deadlines. Completion is recorded only after Firefox reports discarded=true or an automatic reload reaches status=complete on its expected URL. Browser refusal (including beforeunload protection) remains a visible skip rather than a successful unload.

An extension-only top-frame message prefixes the document title with a sleep symbol immediately before discard; cancellation/failure removes the marker. Firefox retains the title of the discarded tab and normal restoration replaces the document. Completed automatic reloads show a reload symbol for three seconds. Cleanup does not overwrite newer site titles. No tab-font, flashing or thumbnail-refresh API is assumed, and feed ordering is not used as proof of a reload. Native validation uses initialized app controls and repeated synthetic input alongside actual typing and audio.

### Background-only automatic reloads (Relay 1.5.2)

Selected tabs in every browser window have no periodic reload alarm. Tab activation cancels the new selected tab's alarm and gives the previously selected tab a full interval starting at deselection. Unrelated background deadlines do not change. Both pre-probe and post-probe guards reject active tabs, so delayed alarms or selection during the form check cannot reload a selected page. Returning never queues catch-up work. Firefox's automatic restore of a discarded tab remains separate. This is a fixed policy: active-tab overrides and new pause labels are deferred to future Relay/site settings, without expanding the popup.

## Productivity tools (Relay 1.6.0 / Widgets 0.6.0)

Temporary pauses are bounded to 256 tab/domain pairs in Relay memory. Each pair may hold independent `reload` and `unload` records with `seconds` and `until`; there is no persisted override schema. The clock's `CYRUNE_TAB_TIMERS` override request names exactly one `kind` (`reload` or `unload`), a mode (`pause` or `none`) and a duration of 1800 seconds, 3600 seconds, or 0 for until-close. Editing/resuming one kind preserves the other deadline. Expiry uses one Firefox alarm and rearms only the affected eligible timer with a fresh interval. Domain changes, close and Relay restart clear both kinds. No saved domain rule is rewritten, and browser-selected/audio/form/private safeguards continue to apply.

Overview bulk actions remain explicit: Keep awake replaces selected tabs' pauses with unload-only pauses, Pause timers sets both, and Resume timers clears both. State/list replies expose the independent records; the overview names each paused service. Reload the extension as a unit when updating the clock/controller; no old-popup runtime branch or persisted migration is needed.

CYRUNE_TAB_TIMERS accepts only the exact clock or timers-overview extension documents, rejects embedded documents, and exposes state/override to the clock. Overview-only list/bulk operations revalidate current tab/domain identity. Lists paginate at 100 rows, search is capped at 128 characters, titles at 160 characters, and bulk selections at 100 unique tabs. Private/non-web tabs are excluded; no original URL is included in list replies or persisted. Bulk overrides report partial failure and never enable disabled saved rules. The overview reuses popup HTML/CSS/JS with view=timers, preserving the exact package allowlist.

cyruneSiteAllowancesV1 is a new independent browser-local schema-1 record with up to 256 domain rules and threshold receipts. Each rule has boolean enabled, integer minutes (1–1440), warningMinutes (0–60, below the limit; 0 off), and boolean block. Disabling a rule retains its settings. Writes commit complete records before replacing live choices; unsupported records are retained/refused. Only currently flagged distracting domains enforce a saved allowance. Collection remains opt-in, and disabled/paused/excluded/idle/private periods accrue no usage. Existing retained daily aggregates determine usage; deletion resets matching recorded usage. Domain-filtered activity reports accept at most 256 canonical domains and aggregate their subdomains before site-list truncation. Per-site warning/limit receipts use local dates and survive restart; notification delivery is best effort after the receipt commits. Midnight refresh resets totals from that day's records. Enforcement reconciles at the existing 15-second cadence and on navigation/rule changes. Firefox blocking authority stays in Relay; neither Portal nor Host needs to run.

Relay 1.6.1 accepts the early schema-1 allowance baseline without an enabled flag (minutes 0 means disabled), converts it once at load, and thereafter uses only the current rule shape. A disabled legacy limit becomes the default 20 minutes with its warning bounded below that limit. One browser.storage.local.set writes both the converted record and the original cyruneSiteAllowancesV1MigrationBackup; an existing backup is preserved. Conversion validates all domains, rules and receipts before writing. Failed writes retain the original. Unsupported data stays intact, and its recovery error is confined to the allowance card; category, exclusion, distraction, scheduled/focus blocking and unrelated navigation remain independent.

Focus review uses the existing SDK activity/report capability filtered by the completed work-phase sessionId. Stop records partial work duration and its phase identity without marking the phase completed. Reviews use retained daily records (up to 365 days), classify non-distracting browsing separately from flagged browsing, and show three main sites. Timer duration is not browsing duration, and missing activity is not backfilled. Legacy/interrupted phases without usable attribution are excluded. Selected review/disclosure belongs only in WidgetSDK local view cache, with cleanup on deletion. No new Portal bridge, native operation, portable data field or IndexedDB migration is introduced.

## Website category taxonomy — 2026-10-25

Current productivity state schema 4 accepts schemas 1–3 through the existing load-boundary migrations. The schema-3 step copies its bounded category map to `categoryMigration.backup`, renames Communication, Entertainment, Learning, News and Social to their expanded equivalents, and normalizes Gaming spelling. Work, Productivity, Personal and Shopping lack a clear one-to-one match and remain intact for manual review, as do custom labels. The timestamped backup and new assignments commit together before live state changes. Failure leaves the original schema-3 record recoverable; loading schema 4 never reruns or replaces the backup. Historical aggregates continue to resolve through current assignments; original activity intervals, distraction flags, exclusions and tracking consent are preserved.

The category defaults contain names only. Retained assignment labels remain selectable alongside the twenty defaults; Uncategorized remains the fallback and last option. New sites remain Uncategorized until manually classified; no automatic network categorization was introduced.
