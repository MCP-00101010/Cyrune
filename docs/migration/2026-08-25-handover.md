## Permanent Structure and Compatibility Decisions

- Morpheus WebHub became **Cyrune Portal**.
- Morpheus EmuGUI became **Cyrune Arcade**.
- The WebExtension became **Cyrune Relay**.
- The native-messaging process became **Cyrune Host**.
- Widgets now live by catalogue category under **Cyrune Widgets**; Portal remains their runtime host.
- Portal and Arcade remain separate applications and interfaces.
- Relay and Host remain separate trust boundaries.
- Both interfaces must continue to work directly from `file://` URLs.
- The retired Arcade/EmuGUI HTTP server was removed before import and must not be restored.
- Existing extension IDs, native-host IDs, credential names, schemas, storage keys, opaque bindings, widget type IDs, and category IDs remain unchanged during this migration.
- Mutable device-local data must ultimately live beneath `%LOCALAPPDATA%\Cyrune`, but only through copy-first, verified, idempotent migration.

## Known Open Widget Bug: ISS Day/Night Rendering

The ISS globe and orbit currently load using the pinned MapLibre GL JS 5.24 baseline, but the night hemisphere and day/night terminator render incorrectly at every zoom level. This is recorded in `Widgets/Widgets-TODO.md` and is not marked fixed.

Important evidence:

- The current ISS JavaScript and CSS were a 100% Git rename from the pre-migration Portal files; no ISS implementation change remains in `74b54ca`.
- The pre- and post-migration ISS widget files and pinned MapLibre 5.24 assets were separately verified as byte-identical during debugging.
- Therefore, do not assume a source-code or zoom-level cause without first comparing effective runtime state.

Do not repeat these failed approaches:

- Upgrading to MapLibre 6.1 ESM was attempted twice. Direct-file loading failed and left the globe/orbit engine unavailable.
- GeoJSON buffer and geometry variations changed the artifacts but did not solve them.
- A raster-image globe overlay warped with the projection.
- A screen-space canvas overlay first disappeared during interaction and later produced a coarse/pixelated edge and terminator. It was reverted.

The next useful ISS investigation is a controlled old-checkout versus Cyrune comparison in the same Firefox session, using identical time, camera, theme, and follow state. Capture console output and compare effective MapLibre style, sources, layers, projection, canvas dimensions, device-pixel ratio, resource URLs, script order, and local storage/origin state before editing the renderer again. Keep MapLibre 5.24 and the currently loading globe as the recovery baseline.

## Remaining Migration Work

At the time of this handover, the unchecked entries in the checklist now archived at `docs/history/cyrune-monorepo-migration.md` were the source of truth. At a high level:

### Remaining Phase 0 follow-ups

- Inventory user bookmarks/shortcuts that still point at old local-page URLs.
- Create verified backups for every remaining runtime source before cleanup or pointer changes.
- Decide whether the single legacy root `backgrounds/` image is referenced; it is not byte-identical to a managed background.
- Confirm the generic ZX launch validator covers the old hard-coded Spectaculator test before removing that script.
- Classify every removed path as generated, runtime, obsolete, or archived.

### Phase 6 — Externalise Portal and Arcade runtime data

Host data is already externalised; Portal and Arcade are not complete.

- Implement one versioned migration coordinator and receipt format.
- Make migration copy-first, reread/parse/hash verified, atomic where practical, retry-safe, and idempotent.
- Distinguish missing, identical, corrupt, divergent, interrupted, and already-migrated states.
- Require an explicit user decision before replacing divergent data.
- Keep receipts free of contents, secrets, approved targets, and credential locations.
- Move Portal's authoritative database, useful backups, and managed backgrounds to `%LOCALAPPDATA%\Cyrune\Portal` only after successful verification.
- Move Arcade configuration, state, managed profiles, and intended cache/log state to `%LOCALAPPDATA%\Cyrune\Arcade`, retaining documented overrides.
- Recheck collections, favourites, history, emulator definitions, profile IDs/hashes, scraper settings, credentials, bindings, and background fingerprints against the recovery inventory.
- Update the user's old Portal/Arcade bookmarks or provide bounded temporary recovery pages if needed.
- Do not move browser-local widget/UI caches or IndexedDB assets unless a separately designed migration requires it.

### Phase 7 — Packaging and automation

- Keep unpackaged Relay source solely in `Relay/`.
- Put generated Relay packages beneath ignored `artifacts/Relay/<version>/`.
- Repair and verify relocated lint/build/package workflows.
- Exclude Host code, installers, tests, live configuration, databases, backups, and credentials from Relay archives.
- Preserve separate unsigned AMO-upload and Mozilla-signed package workflows.
- Verify version alignment and compare a clean-checkout package with the bounded pre-migration workflow.

### Phase 8 — Cutover and monitoring

- Run every still-open item in the validation matrix, including a fresh clone at a different absolute path, installed and temporary extension flows, browser/Host restart, multiple Portal tabs, full Portal/Arcade workflows, archive hash/content checks, and a location-only secret scan.
- Confirm no runtime dependency points at either legacy checkout.
- Document rollback for code, native registration, runtime pointers, and old local-page links.
- Use the monorepo for an agreed monitoring period while keeping old checkouts and runtime sources untouched.
- Archive old sources only after explicit user confirmation. Do not delete them as part of migration completion.
- Reconcile the final remote/cutover checklist: `origin` already points to the user-created Cyrune GitHub repository, but the final monitoring/cutover gate remains open.

## Safety and Recovery Rules

- Do not delete, reset, clean, or rewrite either legacy checkout or the recovery directory.
- Do not print database contents, credential values/names, approved native targets, or embedded icons while auditing.
- Copy and verify before changing a runtime pointer.
- Never overwrite divergent runtime data automatically.
- Preserve direct-file operation and all compatibility-sensitive identifiers.
- Keep product fixes and refactors out of migration phases unless they restore a migration regression; record ordinary product work in the owning component TODO/changelog.
- Run the affected component tests and cross-component checks after every boundary change. Run `web-ext lint` whenever Relay changes and Host tests whenever native behavior or installation changes.
